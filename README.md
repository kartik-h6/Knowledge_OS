# Knowledge OS

> "A personal knowledge system for exploring how healthcare information becomes better understanding, better decisions, better behaviors, and better health outcomes."

---

## Why this repository exists

This repository is not a collection of notes.

It is a thinking system.

Its purpose is to transform everyday learning into connected knowledge that can be applied, communicated, tested, and improved.

Everything I learn—through study, research, clinical exposure, conversations, conferences, books, or projects—enters this system before becoming an article, a presentation, a research idea, a product feature, or a LinkedIn post.

The goal is not to remember more.

The goal is to think better.

---

## Core principle

Information alone rarely changes outcomes.

And the pathway is not automatic:

                CONTEXT
    (language, access, cost, beliefs,
     culture, health literacy, systems)
                     |
                     v
    Information -> Understanding -> Decision -> Action -> Outcome

Context influences every stage.

A person may understand perfectly and still not act because of cost, access, adverse effects, beliefs, fear, family influence, routines, or system barriers.

Everything in this repository explores one part of this pathway.

## Vocabulary

- Publication: Healthcare Knowledge Essays
- Book: major intellectual territory
- Season: smaller arc inside a Book
- Essay #: permanent chronological number. Numbers never change after publication.
- "Chapter": not used.

The essay master index lives in 04_ESSAY_INDEX.md.

## Folders and domains

Folders describe workflow stage (where a note is in its life).

Domains (in 01_KNOWLEDGE_MAP.md) describe topic (what the note is about).

A note lives in one folder and carries one or more domain tags.

---

## The founder framework

05_FOUNDER_FRAMEWORK.md is the operating system for the building side of this work.

The healthcare essays investigate a problem. The founder framework governs how that investigation turns into ventures—how ideas are validated, how value is delivered, and how a business is built around a validated problem rather than a hope. It is the discipline behind projects such as TechStudyHubCore.

It connects to the rest of the repository through the Building domain and the projects/ folder: an essay question can become an experiment, an experiment can become a project, and a project is built using this framework.

Two bodies of work, one method: understand the problem, validate with evidence, and build only what is proven useful.
